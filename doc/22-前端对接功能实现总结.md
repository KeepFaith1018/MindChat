# 前端对接后端功能实现总结文档

## 1. 概述

本文档旨在总结“前端全量对接后端”项目的实施成果。我们基于 `v1` 接口规范，分三个阶段（A/B/C）完成了从模型能力、文件问答到稳定性治理的全链路开发。

---

## 2. 核心功能实现清单

### 2.1 阶段 A：能力基线补齐（模型与 SSE）

- **动态模型列表**：
  - 接入 `GET /models/available` 接口。
  - 前端不再硬编码模型，而是根据后端返回动态渲染下拉菜单。
  - 实现了模型 ID 的自动回落机制（若当前模型不可用，默认选中列表第一个）。
- **能力开关联动**：
  - 接入 `GET /chat/capabilities` 接口获取服务端支持的能力矩阵。
  - 在输入框区域新增“联网搜索”、“深度思考”开关。
  - 实现了“服务端能力约束”逻辑：如果后端返回不支持某能力，前端开关自动禁用并提示。
- **SSE 协议增强**：
  - 完善了 `meta` 事件处理，支持同步服务端下发的 `conversationId` 和实际生效能力。
  - 新增了 `tool_result` 事件处理，支持解析并渲染联网搜索结果（标题、摘要、来源链接）。

### 2.2 阶段 B：上传与文件问答

- **文件上传交互**：
  - 开发了 `FileList` 组件，用于在输入框上方展示已上传的文件（支持移除）。
  - 在 `InputBox` 中集成 `useFileDialog`，支持 PDF/DOCX/TXT/MD 格式选择。
  - 实现了前端前置校验（文件类型 + 10MB 大小限制）。
- **问答上下文注入**：
  - `useChatStore` 新增 `currentFiles` 状态管理。
  - 上传成功后，文件 ID (`fileIds`) 会自动随下一次 `sendMessage` 请求发送给后端，实现基于文件的问答。

### 2.3 阶段 C：错误与稳定性治理

- **统一错误映射**：
  - 建立了 `error-code-map.ts`，将后端业务错误码（如 `46001` 配额不足、`43001` 会话不存在）映射为友好的中文提示。
  - 封装了 `getErrorMessage` 工具函数，统一了 API 和 Store 层的错误处理口径。
- **SSE 稳定性优化**：
  - 配置 `fetchEventSource` 的 `openWhenHidden: true`，防止后台切换导致断连。
  - 细化了重试策略：
    - **401 (未登录) / 404 (会话丢失)**：立即终止重试并跳转/提示。
    - **5xx / 网络错误**：允许自动重试，提升弱网体验。

## 3. 代码变更文件索引

### API 层

- `app/api/models.ts` (新增): 模型列表接口封装。
- `app/api/chat.ts`: 增加 `getCapabilities` 接口。
- `app/api/types.ts`: 补充 `ModelConfig`, `ChatCapabilities`, `ToolResultPayload` 等类型定义。

### Store 层

- `app/stores/useChatStore.ts`:
  - 新增状态：`availableModels`, `currentCapabilities`, `enabledCapabilities`, `currentFiles`。
  - 新增 Action：`loadModels`, `loadCapabilities`, `uploadFile`, `removeFile`。
  - 核心逻辑增强：`sendMessage` 中的 SSE 事件处理 (`tool_result`, `meta`) 及错误处理 (`onerror`)。

### UI 组件层

- `app/components/chat/InputBox.vue`:
  - 集成 `FileList` 组件。
  - 动态渲染模型下拉列表。
  - 增加能力开关按钮组。
- `app/components/chat/MessageList.vue`:
  - 新增工具调用结果 (`toolResult`) 的渲染卡片。
- `app/components/chat/FileList.vue` (新增): 已上传文件展示组件。

### 工具与配置

- `app/utils/error-code-map.ts` (新增): 错误码字典与解析工具。
- `app/utils/api.ts`: 全局增加 `credentials: 'include'` 配置。

## 4. 后续建议

虽然核心功能已对接完毕，但为了进一步提升用户体验，建议后续关注：

1.  **Markdown 渲染优化**：当前代码高亮部分存在 `v-html` 警告，建议引入更安全的渲染库或 sanitizer。
2.  **长列表性能**：如果会话消息非常多，建议引入虚拟滚动 (`virtual-scroller`)。
