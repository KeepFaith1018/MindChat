# AI Chat 流式重构技术升级文档

## 1. 升级背景

本系统原采用 `@microsoft/fetch-event-source` 库处理 SSE（Server-Sent Events）。虽然该库支持 POST 请求，但在以下方面存在局限：

- **依赖性**：引入了额外的第三方包，增加维护成本。
- **集成度**：难以与项目中自定义的 `$api` 请求包装器（支持自动刷新 Token、SSR Cookie 透传、统一错误映射）深度融合。
- **掌控力**：无法精细化控制 `ReadableStream` 的读取逻辑和内存释放。

## 2. 核心实现思路

重构基于 **Fetch API** 和 **ReadableStream**，实现了一套完全自主可控的流式解析方案。

### 2.1 技术栈

- **Fetch API**：现代浏览器原生支持的异步请求接口。
- **ReadableStream**：处理大文件或流式数据的 Web 标准接口。
- **TextDecoder**：高效的二进制到字符串解码工具。
- **AsyncGenerators**：使用 `for await...of` 语法实现非阻塞的流式数据消费。

### 2.2 逻辑架构

1.  **请求层 ($apiStream)**：基于原生 `fetch` 封装，继承了全局 `$api` 的鉴权逻辑。如果 401，会自动执行 `refreshToken` 并静默重试。
2.  **解析层 (parseSSEStream)**：
    - 利用 `reader.read()` 持续读取后端推送到网络层的 chunk。
    - 使用 `buffer` 缓存不完整的消息片段，确保在 `\n\n` 分隔符处切分出完整的 SSE 消息块。
    - 解析 `data:`、`event:` 等字段，转换为标准的 `SSEEvent` 对象。
3.  **消费层 (useChatStore)**：通过异步生成器遍历解析后的事件，根据 `thinking`、`content` 等事件类型实时更新 Pinia 状态。

## 3. 详细技术实现

### 3.1 流式解析器 (stream.ts)

实现了对 `text/event-stream` 协议的严格解析。核心在于处理“半行”数据：

```typescript
// 解析 chunk 并合并缓冲区
buffer += decoder.decode(value, { stream: true })
const parts = buffer.split('\n\n')
buffer = parts.pop() || '' // 保留最后一个不完整块
```

### 3.2 API 包装器集成 (api.ts)

通过 `$apiStream` 统一了流式请求与普通 JSON 请求的底层逻辑。关键点在于 **AbortController** 的传递，使得前端可以随时通过 `abort()` 物理中断 HTTP 连接，节省服务端计算资源。

### 3.3 Store 逻辑解耦

在 `useChatStore` 中，将 SSE 解析逻辑从业务逻辑中抽离：

```typescript
const response = await $apiStream('/chat', { ... });
for await (const msg of parseSSEStream(response)) {
  handleSSEMessage(msg, index);
}
```

## 4. 优化与收益

- **零依赖**：移除了 `@microsoft/fetch-event-source`，减少了项目依赖。
- **极致集成**：流式接口现在自动享受 **Token 自动刷新** 和 **SSR Cookie 同步** 功能。
- **内存安全**：通过 `finally { reader.releaseLock() }` 确保流在异常或中断时能正确关闭，防止内存泄漏。
- **扩展性**：自定义解析器支持 `event` 字段，方便后续扩展如 `tool_call`（多工具并行调用）等复杂交互。
